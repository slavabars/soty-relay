# Модель угроз — релей-хост

**Русский** · [English](threat_model.en.md)

`dtm_host` намеренно прост: он пересылает непрозрачные конверты и отвечает на обнаружение пиров. Этот файл фиксирует, что ему можно и нельзя доверять.

## Активы

- содержимое конвертов — **не** читается хостом (только шифртекст);
- ключи идентичности клиентов — никогда не попадают на хост;
- `host_state.ed_seed` — собственная Ed25519-идентичность хоста, которой подписываются корни pruned-батчей и доказывается идентичность в федерации;
- пины клиентов — каждый клиент помнит Ed25519-ключ хоста, поэтому смена идентичности считается атакой;
- ключи маршрутизации подписчиков (X25519) — нужны для доставки, но недостаточны для расшифровки.

## Противники

1. **Любой подключённый клиент** — может присылать некорректные фреймы, флудить подписками, подделывать конверты и проверять чужие ключи.
2. **Федеративный хост** — может лгать, повторять, удерживать данные или выдавать себя за другого.
3. **Атакующий на пути** — может отбрасывать или повторять трафик между хостом и клиентом.
4. **Тот, у кого есть доступ к файловой системе** — может прочитать `host.db`.

## Цели безопасности

- **Никакого плейнтекста, никогда.** Хост не расшифровывает; у него нет ключей, которые это позволяют.
- **Изоляция доставки.** Подписчик получает только конверты, адресованные его X25519-ключу.
- **Проверка до записи.** Сдвиг часов → подпись → id конверта → дедупликация, именно в этом порядке; неудачный конверт не сохраняется и не пересылается.
- **Ограниченные ресурсы.** Размер фрейма, число соединений, число подписок, списки gossip и окна ограничены до выделения памяти.
- **Идентичность в федерации.** Хост доказывает свой Ed25519-ключ; самозванец не получает конвертов.
- **Долговечность идентичности.** `host.db` не удаляется при обновлении, поэтому пины клиентов остаются валидными.

## Non-goals

- **Скрывать метаданные от оператора.** Оператор видит IP, время подключений, размеры конвертов и ключи маршрутизации. Это неизбежно для релея.
- **Защищать клиента от его собственного устройства.** End-to-end шифрование — задача клиента.
- **Доступность под целевым флудом.** Лимиты ограничивают ущерб, но решительный атакующий всё равно насытит небольшой релей.
- **Доверять оператору.** Клиенты пинят идентичность, но злонамеренный оператор может удерживать или отбрасывать конверты. Soty терпит релеи, но не доверяет им.

## Границы доверия

| Граница | Правило |
| --- | --- |
| сокет → декодер фреймов | максимальный размер фрейма проверяется до выделения памяти |
| фрейм → конверт | строгий разбор; некорректный ввод закрывает соединение |
| конверт → база | только после проверки сдвига часов, подписи и id |
| база → подписчик | право по X25519-ключу, а не по порядку подключения |
| хост ↔ хост | доказательство идентичности + announce-адрес; неизвестные хосты ничего не получают |

## Операционные инварианты

- никогда не удалять и не коммитить `host.db`;
- никогда не логировать содержимое конвертов, ключи и seeds;
- в продакшене TLS терминируется перед релеем; юнит несёт `--announce`;
- релей работает с минимально нужными привилегиями (user-юнит или shell-супервизор, без root после установки).

Эксплуатируемые детали и их исправления ведутся в приватном журнале аудита.
