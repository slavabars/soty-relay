# dtm_relay — релей Soty для OpenWrt

`dtm_relay` — это LAN-релей и трекер Soty для роутера с OpenWrt. Он принимает только непрозрачные зашифрованные конверты, хранит их для офлайн-доставки, отдаёт подписчикам и отвечает на запросы трекера. Протокол WebSocket побайтово совместим с `dtm_host`, поэтому приложение подключается к роутеру тем же приглашением `soty://host?...`, что и к интернет-релею.

Роутер нужен, когда интернета нет: устройства в одной локальной сети обмениваются сообщениями через него, не теряя историю при уходе отправителя в офлайн.

## Зачем отдельная реализация на Go

`dart compile exe` собирает бинарь под glibc и не поддерживает musl, а типовой роутер работает на musl/mipsel (MT7621) или musl/aarch64. Поэтому `dtm_host` на роутер не переносится. `dtm_relay` собирается статически (`CGO_ENABLED=0`) и не зависит от разделяемых библиотек роутера.

Для mips/mipsle обязателен `GOMIPS=softfloat`: у большинства таких SoC нет FPU. `openwrt/build-ipk.sh` уже передаёт нужные флаги.

## Сборка

```sh
cd host/relay-owrt
make test          # go test ./...
make               # vet + test + локальный бинарь в dist/
make ipk           # .ipk для mipsel_24kc, mips_24kc, aarch64, armv7, x86_64

# релизный bundle: пять .ipk + SHA256SUMS + README.txt
VERSION=X.Y.Z+N ./openwrt/build-bundle.sh
```

Один пакет: `openwrt/build-ipk.sh mipsel_24kc` → `dist/dtm_relay_<version>-1_<arch>.ipk`. Зависимостей у пакета нет: бинарь статический. Формат `.ipk` — gzip-tar (`debian-binary`, `control.tar.gz`, `data.tar.gz`), как его читает opkg в OpenWrt 24.10+; на более старых релизах используйте buildroot-пакет (там формат собирает сама OpenWrt).

`openwrt/Makefile` — канонический пакет для OpenWrt buildroot (feed). Проверенный на обычном Linux путь — `build-ipk.sh`; buildroot-версия требует SDK и раскладки, где исходники лежат рядом с каталогом `openwrt/`.

## Установка

```sh
tar -xzf dtm_relay-X.Y.Z+N-ipk.tar.gz
sha256sum -c SHA256SUMS
opkg install dtm_relay_X.Y.Z+N-1_mipsel_24kc.ipk
uci set dtm_relay.relay.enabled='1'
uci set dtm_relay.relay.port='3100'
uci commit dtm_relay
/etc/init.d/dtm_relay enable
/etc/init.d/dtm_relay start
```

В логе и на stdout будет приглашение:

```text
soty://host?addr=ws%3A%2F%2F192.168.1.1%3A3100%2Fws&pk=<ed25519>
```

Его можно отправить контакту или открыть на устройстве. Приложение добавляет релей по deep link и подписывается на него. Если `announce` пуст, init-скрипт подставляет адрес `br-lan` (запасной вариант — адрес из UCI); при ручном запуске бинарь по умолчанию даёт `ws://127.0.0.1:<port>/ws`, поэтому для LAN укажите `--announce` явно.

Порт слушается на `0.0.0.0`, но рассчитан на локальную сеть; зона `lan` в OpenWrt по умолчанию принимает входящие, отдельное правило нужно только если вы ужесточили firewall. Не пробрасывайте `ws://` в интернет: публичный релей должен быть за `wss://` (nginx), иначе трафик можно читать и подменять на пути, хотя содержимое конвертов всё равно зашифровано.

## Настройки UCI

| Опция | По умолчанию | Что делает |
| --- | --- | --- |
| `enabled` | `1` | Запускать ли релей |
| `port` | `3100` | Порт WebSocket `/ws` |
| `announce` | авто | Публичный `ws://`/`wss://` URL; пусто — init-скрипт подставляет LAN-адрес роутера (`ws://<lan-ip>:<port>/ws`) |
| `identity` | `/etc/dtm-relay/identity` | Файл Ed25519-seed, права `0600` |
| `retention_days` | `30` | Сколько держать конверты подписанных получателей |
| `max_connections` | `128` | Потолок одновременных сокетов (жёсткий максимум — 512) |
| `storage` | `memory` | `memory` (RAM) или `disk` (журнал на USB) |
| `path` | `/tmp/dtm-relay` | Каталог журнала для `storage=disk` |
| `federation` | `0` | Федерация с интернет-релеями, по умолчанию выключена |
| `seeds` | пусто | Seed-адреса через пробел, каждый `url` или `url\|pk` |

## Хранение и идентичность

По умолчанию очередь живёт в RAM. Это осознанный выбор: флеш роутера изнашивается, а 30-дневное хранение на 128 МиБ памяти всё равно невозможно. При перезагрузке очередь теряется, зато подписки и устройства переподключаются сами.

`storage=disk` включает append-only журнал `envelopes.ndjson` в `path` (например, на USB-накопителе). Журнал переписывается при prune и при остановке, поэтому не растёт бесконечно. `fsync` на каждую запись не делается: при внезапном отключении питания последние конверты могут потеряться, это допустимая цена за ресурс флеша.

Идентичность всегда лежит в `/etc` (по умолчанию `/etc/dtm-relay/identity`) и **никогда не удаляется**: клиенты пиннят Ed25519-ключ, и его потеря означает `IDENTITY CHANGED` для всех, кто добавил этот релей. Файл создаётся с правами `0600`, каталог — `0700`. Повреждённый файл — ошибка запуска, а не повод сгенерировать новый ключ.

В памяти действуют жёсткие потолки: не более 20 000 конвертов и 32 МиБ; самые старые вытесняются первыми. Это кэш, а не обещание хранения: подписанные Merkle-корни prune покрывают только возрастную и оконную очистку.

## Федерация

По умолчанию релей обслуживает только свою LAN и **не открывает исходящих соединений**. Это важно для роутера: он не должен превращаться в открытый ретранслятор без ведома владельца.

Федерация включается явно:

```sh
uci set dtm_relay.relay.federation='1'
uci set dtm_relay.relay.seeds='wss://soty.su/soty-ws|fad55cc7...'
uci commit dtm_relay
/etc/init.d/dtm_relay restart
```

С `federation=0` любой `dtm-host` в HELLO остаётся обычным клиентом: чужие конверты ему не пересылаются. С `federation=1` работают те же правила, что у `dtm_host`: роль релея выдаётся, а не заявляется, ключ пинится, если задан в seed, а анти-энтропия идёт через `WANT`/`HAVE`/`GET`/`ENVELOPES` и `NETWORK`.

## Эндпоинты

| Путь | Назначение |
| --- | --- |
| `/ws` | Протокол релея и трекера (WebSocket) |
| `/status` | Агрегированные счётчики и здоровье процесса, без ключей и адресов |
| `/healthz` | `{"ok":true}` |
| `/directory` | Публичная запись релея: свой адрес и Ed25519, плюс федеративные члены, доступные из интернета |

## Безопасность и лимиты

- Конверты непрозрачны: релей проверяет подпись и id, но никогда не расшифровывает и не логирует ciphertext или plaintext.
- Порядок проверки фиксирован: rate limit → clock skew → Ed25519 → id → dedup.
- Все числа скопированы из `app-src/lib/core/security_limits.dart` в `internal/limits`; расхождение видно в диффе. Кадр — 256 КиБ, ключей подписки — 16 на соединение, элементов gossip — 256, hop ceiling — 3, presence — 64 ключа, известных пиров — 8192.
- Дубликаты по id отбрасываются, окно `since` подрезается 30 днями, подписки и пиры имеют TTL.
- В `/status` нет идентичности, адресов клиентов и метаданных конвертов.

## Проверка

```sh
go test ./...
python3 ../../scripts/host_probe.py ws://192.168.1.1:3100/ws <pinned-ed25519>
```

`host_probe.py` выполняет тот же handshake и проверку ключа, что приложение при добавлении релея. Для сквозной проверки с настоящим кодом приложения (не только Go-клиентом) есть `../tool/interop_relay.dart`: он подключается к запущенному релею, подписывается, публикует и принимает конверт, созданный `createEnvelopeForPubKey`, и проверяет presence, `PEER_LIST` и live-доставку.

## Бекап перед тестом на роутере

Любой тест на рабочем роутере начинается с проверенного бекапа: `sysupgrade -b`, копия overlay upper, `/etc`, список пакетов и SHA-256. Установка допускается только после того, как бекап скачан и сверен; откат должен вернуть те же `uci export` и `opkg list-installed`. Готовый bundle публикуется в релизах Soty как `dtm_relay-X.Y.Z+N-ipk.tar.gz`, отдельные `.ipk` в релиз не прикладываются.

## Что не входит в эту версию

- Медиа по радио и любые LoRa-функции — это отдельные задачи (`T-108`…`T-118`), шлюз `dtm_lora_gw` живёт отдельно.
- TLS-терминация на самом роутере: `wss://` настраивается nginx, релей остаётся на loopback.
- Полноценная замена `dtm_host` на сервере: у серверного хоста SQLite, Merkle-аудит и больший потолок соединений; роутер обслуживает одну LAN.
